# 遊戲設計

## 類型定位

**《下班要做什麼?》** 是原創 Web 社交生活模擬。它的重點不是打怪、破關或分數競賽，而是讓居民在下班後的社區中自動互動，玩家像管理員一樣觀察、照顧與輕度介入。

## 玩家身份

玩家是 **人際觀察者 + 半個月老**。玩家主要觀察居民下班後的生活，也能有限介入關係與事件結果。

玩家能做的事情：

- 新增居民。
- 查看居民狀態。
- 回應居民需求。
- 贈送食物、禮物或服裝。
- 安排居民聊天或活動。
- 查看事件紀錄。
- 逐步解鎖社區區域。

## 操作模式

本遊戲採用手機橫向優先的點選操作。桌面 Web 也要支援，但所有主要流程都必須能用手機橫向、單指完成。

主要操作：

- 點選居民：打開居民詳情。
- 點選事件：打開事件面板。
- 點選選項：執行送食物、送禮、安排聊天、安撫等行動。
- 點選側邊導覽：切換社區、居民、事件、物品、設定。
- 長按可作為後續擴充，但 MVP 不依賴長按。

限制：

- 不依賴滑鼠 hover 顯示關鍵資訊。
- 不依賴右鍵。
- 不要求精準拖曳。
- 不要求快速反應或連續按鍵。
- 不把主要按鈕放在手機難以點選的位置。
- 直向手機可顯示旋轉提示或基本相容版面，但 MVP 以橫向為準。

## 核心場景

MVP 場景採用「下班生活圈」，包含：

- 住宅區：社區大樓、出租套房、老公寓或住商混合大樓。承載鄰居、前任住附近、深夜拜訪、曖昧串門等事件。
- 便利商店：買宵夜、偶遇、撞見曖昧對象和別人在一起。
- 餐酒館：下班聚會、喝一杯、三角關係、前任修羅場。
- 公園或河堤：談心、告白、分手、冷靜。
- 捷運口或公車站：錯過、偶遇、跟誰一起回家。

共享公寓不作為主設定，但可作為住宅區的一種變體。

### 居民

每位居民至少包含：

- `id`
- `name`
- `avatar`
- `personality`
- `lifeBackground`
- `housingType`
- `financeState`
- `mood`
- `energy`
- `hunger`
- `socialNeed`
- `likes`
- `dislikes`
- `relationships`
- `memoryLog`

### 人生背景

居民不只是一組個性，還需要有人生起點。玩家可以設定或抽選居民背景，背景會影響住處、金錢壓力、人際事件與可觸發的 drama。

MVP 可先提供：

- 含著金湯匙：家境好、壓力低，但容易觸發被利用、被誤會、價值觀衝突。
- 背債務：金錢壓力高，容易觸發借錢、兼職、催繳、感情壓力事件。
- 普通上班族：穩定但疲憊，容易觸發加班、聚餐、通勤、曖昧日常。
- 月光族：享樂高、存款低，容易觸發衝動消費、聚會邀約、月底吃土事件。
- 家裡有房：居住穩定，但容易觸發親友借住、家人干涉、房產比較。
- 北漂或外地打拚：社交需求高，容易觸發孤單、租屋、同鄉、前任遠距事件。

### 住處設定

住處不是固定世界設定，而是居民設定的一部分。不同居民可以住在不同類型的地方。

可選住處：

- 社區大樓。
- 出租套房。
- 老公寓。
- 住商混合大樓。
- 家裡提供的房子。
- 臨時借住。

住處會影響事件：

- 出租套房：房租壓力、鄰居噪音、曖昧串門。
- 老公寓：鄰居八卦、設備壞掉、樓梯偶遇。
- 住商混合大樓：樓下偶遇、便利商店事件、餐酒館聚會。
- 家裡提供的房子：被說靠家裡、親友干涉、價值觀衝突。
- 臨時借住：尷尬同居、前任收留、友情壓力。

### 個性

MVP 可先提供 5 種個性：

- 開朗：更容易主動社交。
- 冷靜：情緒波動較小。
- 害羞：較少主動社交，但深度關係成長較快。
- 講究：對禮物與環境更挑剔。
- 奇想：更容易觸發怪趣事件。

### 關係

居民之間的關係以數值和標籤表示：

- 陌生。
- 認識。
- 朋友。
- 好朋友。
- 暗戀。
- 曖昧。
- 交往中。
- 前任。
- 尷尬。
- 爭執中。
- 三角關係。
- 第三者。
- 多人追求。
- 后宮式關係網。

MVP 需要支援暗戀、曖昧、交往、分手、前任與第三者傳聞。后宮式關係網保留為後續擴充。

所有戀愛與 drama 相關居民都應預設為成年人。事件文字應避免露骨性描寫，以社交誤會、情感選擇、八卦、吃醋、修羅場和關係後果為主。

內容尺度定為 15+：可有第三者、劈腿疑雲、前任修羅場、多人追求，但不做露骨描寫。

### 事件

事件是遊戲的核心內容。每個事件由條件、文字、玩家選項與結果組成。

MVP 事件類型：

- 居民餓了，想吃東西。
- 居民心情不好，想找人聊天。
- 兩位居民第一次認識。
- 兩位居民聊天變熟。
- 兩位居民發生誤會。
- 居民暗戀另一位居民。
- 曖昧對象同時被其他居民邀約。
- 前任突然出現在同一個活動。
- 第三者傳聞讓居民心情下降。
- 背債居民被邀請去高消費餐酒館。
- 含著金湯匙居民被懷疑用錢解決問題。
- 月光族居民月底只能在便利商店解決晚餐。
- 家裡有房居民被朋友拜託借住。
- 居民想要新物品。
- 居民分享今日小故事。
- 居民邀請另一位居民參加活動。

### 玩家介入

MVP 行動：

- 送食物：改善飢餓與心情。
- 送禮物：影響喜好與關係。
- 安排聊天：推動兩位居民互動。
- 安撫居民：降低負面心情。

### 長期目標

MVP 主指標：

- 社區活躍度。
- 事件收集率。

副指標：

- 八卦熱度。

遊戲不設傳統勝敗，而是透過事件收集、居民關係變化和社區活躍度提供長期目標。

## 遊戲循環

1. 社區狀態推進。
2. 系統檢查居民需求與關係。
3. 產生一個或多個事件。
4. 玩家選擇介入行動。
5. 系統更新心情、需求、關係與事件紀錄。
6. 畫面顯示社區變化與居民回饋。

## MVP 畫面

至少需要：

- 像素風社區總覽。
- 居民列表。
- 居民詳情。
- 事件面板。
- 物品或行動面板。
- 設定與存檔狀態。
- 手機橫向側邊導覽列。

社區總覽應以橫向像素地圖呈現，住宅區、便利商店、餐酒館、公園或河堤、捷運口或公車站都應是可點選區域。

## 可玩性的重點

- 事件文字要短、明確、有性格。
- 每次玩家行動都要有狀態變化。
- 居民不能只是資料表，需要有可觀察的差異。
- 關係網要能累積，讓玩家覺得社區有歷史。
- 手機版每個主要互動目標都要足夠大，避免誤觸。
- 關係 drama 要有後果，例如心情下降、信任變低、關係轉冷、八卦擴散或和解成功。

## 後續擴充

- 更多個性。
- 更多事件模板。
- 服裝與房間裝飾。
- 真實時間事件。
- 節日活動。
- 社區區域解鎖。
- 截圖或分享卡片。
