# MVP 與里程碑

## Phase 0：需求收斂

目標：把參考遊戲轉換成合法、原創、可實作的 Web 版方向。

項目：

- 確認參考遊戲為社交生活模擬。
- 決定原創遊戲名稱與社區主題。
- 確認遊戲名稱為「下班要做什麼?」。
- 確認手機版以橫向操作為主要基準。
- 確認 MVP 美術風格為像素風。
- 定義居民資料結構。
- 定義 MVP 事件類型。
- 定義現實人際 drama 的尺度與分級。
- 定義不使用 Nintendo、Mii 或原遊戲素材的素材規範。

完成條件：

- `docs/GAME_DESIGN.md` 記錄 MVP 玩法。
- MVP 不再依賴原遊戲名稱、角色或素材。
- 技術方向以資料驅動生活模擬為核心。

## Phase 1：生活模擬原型

目標：做出最小可玩的居民生活循環。

項目：

- 建立 Vite + TypeScript 前端專案。
- 建立居民資料模型。
- 建立心情、需求與關係狀態。
- 建立事件產生器。
- 建立玩家介入行動。
- 建立本機存檔。
- 建立社區總覽、居民列表與事件面板。
- 建立手機橫向側邊導覽與觸控點選流程。

完成條件：

- 玩家可以查看 3 至 5 位居民。
- 系統會自動產生日常事件。
- 玩家行動會改變居民狀態或關係。
- 重新整理後能保留進度。
- 手機橫向瀏覽器可完成主要流程。

## Phase 2：體驗打磨

目標：讓社區像真的在生活。

項目：

- 加入更多事件模板。
- 加入居民喜好與厭惡。
- 加入事件紀錄與居民回憶。
- 加入手機版互動調整。
- 加入基礎動畫與音效。
- 加入重置存檔與設定。

完成條件：

- 新玩家能在 30 秒內理解玩法。
- 居民之間能形成可觀察的差異。
- 手機與桌面版面都能正常操作。

## Phase 3：內容擴充

目標：增加可重玩性與居民故事量。

項目：

- 新增更多個性。
- 新增更多食物、禮物與活動。
- 新增社區區域，例如廣場、公園、商店、餐酒館、便利商店。
- 新增居民成就或回憶收藏。
- 新增社區活躍度與解鎖條件。

完成條件：

- 玩家有理由持續回來查看居民。
- 事件組合不容易重複到無聊。
- 內容資料能用設定檔擴充。

## Phase 4：發布準備

目標：整理成可部署版本。

項目：

- 建立 production build。
- 加入核心規則測試。
- 加入瀏覽器互動測試。
- 檢查效能與載入大小。
- 補齊素材來源與授權。
- 部署到目標平台。

完成條件：

- `npm run build` 可成功。
- 可在部署網址正常遊玩。
- README 有清楚啟動、測試、建置與部署說明。
